# v0.11-clean — every promise kept in exactly one place

*Concept note, 2026-08-01. Fifth in the series: `triage-design.md`,
`transport-design.md`, `v0.8-concept.md`, `v1-roadmap.md`. This is the
clean-room implementation concept for the v0.10 → v0.11 gate ("surface"):
same features, same frozen wire, different construction. It deliberately
ignores HOW the shipped v0.11 was built and keeps only WHAT it proved.*

## The finding that shapes everything

The shipped v0.11 delta is ~15,500 lines against a v0.10 codebase of 8,842.
Roughly 5k of it is source, 9k is tests, and the review of that diff found
its signature everywhere: **every promise is enforced separately at every
place it could break.** Six state getters each carry a `create=` flag and
their own symlink check; uninstall's preview and executor are two
hand-written walks of the same tree that must be kept in agreement (and
three review findings later, weren't); each fence carries its incident
story as a comment and 3–5× its size in mutation tests. The fences are
individually excellent — and the sum is a wall built brick by brick, each
brick mortared on the day something leaked through the gap where it now
sits.

That is defense by accretion. It works (the red team confirms it), but it
scales linearly with incidents, and its correctness lives in the
*discipline of the next contributor* — exactly the property v1.0 exists to
remove ("the burden of proof moves from the builder into the artifact").

> **v0.11-clean makes each defect class unrepresentable instead of fenced.
> One promise, one place, one test.**

The feature target is unchanged and non-negotiable — the contract is the
spec (`v1-contract.md`): envelope normalization (§1's conformance table
closed, §3.4 send codes wired), the outputSchema freeze (§8), the lifecycle
(`setup` / `doctor --fix` / `update` / `uninstall`), the collapse of six
state overrides into one root, packaging + CI. The shipped v0.11 froze that
wire; the clean build must land on the *same frozen surface*, byte for
byte. That is a gift, not a constraint: the frozen snapshots and the
contract's conformance table are an implementation-independent acceptance
suite that already exists.

## The five primitives

Everything v0.11 does is an instance of one of five ideas. Each becomes one
module, owns its whole promise, and is the only place that promise lives.

### 1. `state.py` — the filesystem as a capability, not a convention

Today the rule "reads must never create" is a convention re-implemented as
a `create=` flag in six getters, and "never write through a symlink /
never manage $HOME / never adopt a foreign directory" is a set of checks
repeated wherever someone remembered. Clean version:

```
State.resolve(env) -> Resolved(root) | Refused(reason)     # pure, total
Resolved.reader()  -> StateReader                          # cannot create, ever
Resolved.adopt()   -> StateWriter | Refused(reason)        # the ONE effectful door
```

- **All path policy lives here**: home-or-above (by inode, not spelling),
  symlink fences, marker semantics, retired-var rejection, the
  normpath/expanduser edge cases. Defined once, tested once, as a
  table-driven policy suite.
- **`StateReader` has no create methods.** A read path creating state stops
  being a bug class and becomes a type error. The `create=False` flag —
  and the possibility of forgetting it (the shipped build's graph.py did) —
  does not exist.
- **`Refused(reason)` is a value, not an exception.** Doctor renders it,
  the server refuses on it, the CLI prints it — one reason string, so the
  "every reporting surface must agree" problem (a whole commit-theme of the
  shipped build) is agreement by construction: there is only one source.
- Every entry point does `State.resolve()` exactly once, at the top.
  `startup_guard`, per-tool config gates, and per-repair refusal checks all
  collapse into that single resolution.

### 2. `envelope.py` — the wire boundary as one total function

Today tools return hand-shaped dicts; the belt catches escapes; a bespoke
prober crawls fixture-driven envelopes to freeze their shapes. Clean
version: **tools are pure functions returning typed values or raising
typed errors.**

- Results are frozen dataclasses (`EmailFull`, `ThreadRefs`, `SendReceipt`,
  …). Errors are a closed hierarchy keyed 1:1 to the §3 code namespace
  (`NotFound`, `InvalidInput`, `MailUnavailable`, `SendRefused(code)` …).
- One `@tool` decorator is the entire wire boundary: value → `{ok: true,
  …}`, typed error → `{ok: false, code, error, fix?, operation_id?}`,
  unknown exception → `internal_error` + full traceback to the file log.
  Byte-bounding of failure prose and the minted-id gate on `operation_id`
  live here and nowhere else — there are no other `ok: false`
  construction sites to bound.
- **The outputSchema freeze becomes derivation, not exploration.** The
  frozen schema is generated from the dataclass types (a ~50-line
  walker), dumped canonically, and diffed against the checked-in file.
  Every variant a tool can return is a type, so every variant is frozen —
  the shipped prober's known seam ("one success variant per tool") closes
  itself. The checked-in v0.11 snapshot is the compatibility oracle: the
  derived schemas must match it.
- The §3 exception→code map (`_classify`) is kept as-is conceptually —
  it was already single-sourced and correct in the shipped build; here it
  is simply the constructor table of the error hierarchy.

### 3. `plan.py` — destructive work as data

The shipped build's uninstall preview and executor are ~350 lines of
paired walks; three of the review's findings (silent log-failure
swallowing, the "is intact" overclaim, preview lines the executor then
refuses) are all *disagreements between the two walks*. Clean version:
**one Action algebra, computed once, consumed twice.**

```
Action = UnlinkFile | RemoveTree | RenameAside | Chmod | BootoutAgent | WriteFile
plan_uninstall(state, purge) -> list[Action | Kept | PrintOnly]
render(plan)  -> the preview text            # pure
execute(plan) -> list[ActionResult]          # the ONLY effectful walk
```

- Preview and execution cannot diverge: they are the same list. "Left
  behind" is `[r for r in results if r.failed]` — a failure that doesn't
  reach the exit code is unrepresentable, because the exit code is a fold
  over the same results the messages come from.
- **Fences live in the Action constructors.** `RemoveTree.at(path)`
  refuses (returns `Refused`) on symlink/home/non-dir at *construction*
  time, so the preview already shows the refusal the executor would hit —
  the plan is honest because a refusable action never enters it. The D7
  purge fences (hardcoded `~/.email-mcp`, lstat, fd-based rmtree) are the
  `RemoveTree` implementation, written once.
- Partial-failure honesty is structural: `ActionResult` carries
  before/after existence, so "removed / still present / partly removed —
  check yourself" is derived from evidence, never asserted.

### 4. `checks.py` — one registry behind doctor, --fix, and setup

The shipped build has four sibling walkers over the same facts: doctor's
checks, the repairs registry, setup's preflight steps, and health.py's
caveats — kept consistent by care. Clean version: **one Check type.**

```
Check = (id, probe: StateReader -> Finding | None, repair: (StateWriter -> Action) | None)
```

- `doctor` = run probes, render findings (read-only by type: probes get a
  `StateReader`).
- `doctor --fix` = for each finding with a repair, build the Action and
  hand it to `plan.execute` — the same executor uninstall uses, so audit
  events, dry-run purity, and failure honesty are inherited, not
  re-implemented. `--dry-run` is `render(plan)` — pure by the same
  argument as uninstall's preview.
- **Repairs receive a `StateWriter`, which cannot exist for a refused
  root.** The shipped build's worst surviving defect (the audit-squat
  repair mutating under a refused root — the one repair that skipped the
  gate) becomes uncompilable rather than untested.
- `setup` is the same registry run forward: a wizard is prompts + the
  subset of checks whose repair is "create it" + a smoke test. `update` is
  checks whose probe compares `meta.json`'s state_version. Whole-cloth
  step frameworks are not needed.

### 5. `cli.py` — dispatch and nothing else

Verbs compose the four primitives: `setup`/`update`/`uninstall`/`doctor`
are each a ~40-line orchestration (resolve state → build plan/checks →
render → confirm → execute → fold exit code). Bare invocation serves, as
the shipped build correctly decided (D2); legacy dash-flags forward to
`server.main`. The typed-confirmation, `--yes`, and audit-event-before-
destruction rules live in one `confirm_and_run(plan)` helper shared by
every destructive verb.

## What the 15k build teaches (and is kept)

The shipped build's real asset is not its code — it is its **incident
catalog**: firmlink inode identity, `~nosuchuser` expanduser, deleted-cwd
`absolute()`, the marker adoption race, ENAMETOOLONG misclassification,
`Path.glob` swallowing PermissionError, the umask-vs-mkdir mode dance,
mcp 2.0 removing fastmcp. Every one of those becomes a **row in the policy
tables** of the relevant primitive's test suite (state policy, envelope
classification, action fences) — the lessons survive as data, the
scaffolding that discovered them does not. `docs/security-posture.md` on
main remains the narrative record; this build cites it instead of
re-narrating it in comments.

Also kept verbatim from the shipped decisions: rejection (never silent
migration) of the six retired variables; `pipx` + the name decision;
`mcp>=1.2,<2`; version single-sourced from `__init__.py`; macOS-only CI on
3.11/3.14; deliberate semver tags; the additive-only audit event types
(`doctor_fix`, `lifecycle`).

## What is deliberately NOT here

- **No `create=` flags, no per-getter fences, no per-repair gates, no
  second preview walk, no bespoke schema prober** — each is subsumed by a
  primitive above; their reappearance in review is the smell that the
  concept is being abandoned.
- **No new features.** Same 20 tools, same 11 read-only set, same codes,
  same caps, same audit schema. The wire must be indistinguishable from
  shipped v0.11 — the frozen snapshots decide, not opinion.
- **No framework.** Five plain modules; dataclasses and functions; zero
  new dependencies.

## Size and test budget

Honest estimates, to be measured at the gate, not asserted after it:

| Piece | Source | Tests |
|---|---|---|
| `state.py` (+ config slimming) | ~350 | ~450 (policy tables) |
| `envelope.py` + typed returns in server | ~450 | ~350 (incl. derived-schema freeze) |
| `plan.py` | ~250 | ~300 |
| `checks.py` (doctor/fix/setup/update content) | ~450 | ~450 |
| `cli.py` + packaging/CI | ~250 | ~250 |
| red-team pass (once, against primitives) | — | ~400 |
| **Total** | **~1,750** | **~2,200** |

Against the shipped ~5k source + ~9k tests: a ~3.5× reduction, from the
same feature set — because a promise kept in one place is tested in one
place, and the mutation-test mass that mirrored every scattered fence
collapses into policy tables.

## Sequencing

1. **`state.py`** — port the six getters' consumers onto it; delete the
   flags. (Everything else stands on this.)
2. **`envelope.py` + typed returns** — N1 and N2 fall out together; the
   frozen v0.11 snapshots gate the port tool by tool.
3. **`plan.py` + `checks.py`** — uninstall first (it exercises execute),
   then doctor/--fix/setup/update as registry content.
4. **`cli.py`, packaging, CI** — mechanical once 1–3 stand.
5. **One red-team stage against the primitives** — attack `state`,
   `RemoveTree`, and the decorator, not twenty call sites. Findings become
   policy-table rows.

Acceptance for the whole branch: the v0.11 frozen snapshots match; the
contract §1 conformance table reads "v0.11" in every row; the shipped
build's *behavioral* red-team scenarios (re-expressed against the
primitives) pass; a clean-venv wheel install serves.

## Why this is the beautiful version

The shipped v0.11 kept every promise by standing a guard wherever a
promise had once been broken. This version keeps each promise by making
its violation inexpressible: reads cannot create because readers have no
create; previews cannot lie because they render the plan that runs; a
repair cannot touch a refused root because no writer exists for one; a
schema cannot drift unfrozen because schemas are derived from the types
that produce the data. A stranger who asks "where is this guaranteed?"
gets one file per guarantee — and the diff a stranger reviews is a third
the size, saying the same things once.

The one-line version: **v0.10 made every claim accountable; v0.11-clean
makes every promise structural.**
